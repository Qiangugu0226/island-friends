## 2. 建议的 P5 执行顺序

1. **A1 + A2 + A3**（贴图 + 瓦垄 + 墙缝）→ 一版就能看到质变
2. **B1 + B2**（色彩分级 + 接触阴影）→ 画面立刻"高级"
3. **C1 + C2 + C3**（夜灯 + 萤火 + 灯塔光束）→ 夜晚成为亮点
4. **D1 + D2**（动作曲线 + 风摆）→ 画面"活"起来
5. A4/A5、B3/B4、C4/C5/C6、E1–E3 → 收尾

## 3. 明确不做的（性价比低）

| 不做 | 原因 |
| --- | --- |
| 体积光 / 浅景深 | Three.js 里成本高、移动端掉帧，收益不如色彩分级 |
| PBR 物理材质 | 和手绘卡通风格不搭，反而失去"干净色块"的优点 |
| 写实水面倒影 | 用立方体贴图不值得，简化版波纹+泡沫更划算 |
| 外部模型/贴图资源 | 现在全程序化，引入资源会带来管线与体积成本 |

## 4. 性能红线

- 目标：**桌面浏览器 60fps**，draw call 控制在 **2000 以内**（现在约 1100-1300）
- 粒子一律用 InstancedMesh 或 Sprite 池
- 贴图分辨率上限 512×512（手绘噪点不需要更大），全部程序化生成

### P5-2 · 色彩分级 + 接触阴影 — tag ``p5.8-art-postfx``

计划里的 **B1（色彩分级）+ B2（接触阴影）**，两项一起做，因为它们是"画面立刻高级"的同一批。

**B1 色彩分级**：``src/core/grade.js`` —— 场景先画进离屏缓冲，再用一个全屏 pass 调色：
曝光 / 对比（围绕 0.5 的 S 曲线）/ 饱和 / **暖高光 + 冷阴影**（分离调色）/ 暗角 / 暗部提亮。
颜色空间手工处理：场景渲染出线性值 → 在 sRGB 显示空间调色（和调色软件滑块手感一致）→ 自己编码回 sRGB 输出，
所以"开 / 关分级"的对照是干净的（不是把两张色彩空间不同的图放一起比）。

**抗锯齿的取舍（实测数据）**：离屏缓冲上开 MSAA 太贵 —— 4xMSAA 让帧时间 **177ms → 317ms**（几乎翻倍），
2xMSAA 也一样；改成**不开 MSAA + 着色器内 FXAA** 后是 **157ms**（比基线还略快，因为省掉了画布 MSAA 的解析）。
所以默认 ``samples: 0 + fxaa: true``。

**B2 接触阴影**：``src/core/contact-shadows.js`` —— 在物件底部铺一张程序化柔边暗片（中心实、边缘散、边缘故意不规则）。
太阳的实时阴影解决"有光时的投影"，这张暗片解决"物件和地面的接缝"（墙角、桶底、树根），
两者叠加才是"压在地上"的感觉。**524 片合并进 1 个 InstancedMesh → 只多 1 个 draw call**（实测只 +6ms）。

**调参入口**：``world.json`` 的 ``grade`` / ``contactShadows`` 两段是全部可调参数；
URL 里可以实时改：``?grade=0`` 关分级 · ``?shadows=0`` 关暗片 · ``?samples=4`` 换 MSAA 档 ·
``?sat=1.2&contrast=1.1&vignette=0.3&warm=1.2&cool=0.8&exposure=1.05&lift=0.02`` 逐项试数值。

**新增回归测试**：``tools/test-postfx.mjs`` —— 在同一页面里开关分级，逐像素对比：
必须"有变化（真在调色）但不过分"，并且**画面不能是全黑/纯色**。
（这个测试就是抓"离屏纹理没接上 → 全黑"那类静默故障的：这次它当场抓到了 ``tDiffuse`` 忘了赋值。）

**对照图**（同机位、同时刻、四种组合）：``shots/p5g-{day,base,dusk,night}-{off,shadow,grade,both}.png``
